#+TITLE: Dockers

This repository contains Docker images that I regularly use. [[./Makefile][Makefile]] builds the
images and [[./aliases.sh][aliases.sh]] defines the shell functions that drive them.

#+begin_src shell
source aliases.sh   # bash only — it uses BASH_SOURCE
make                # every image, or: make <image>
#+end_src

* base-* images

These are the custom images that I use as base for other images. They contain
useful small utilities like /tmux/, /nano/, /git/ and /curl/.

- [[./base-alpine][base-alpine]]

/nxc all the things/:

- [[https://github.com/dirkjanm/BloodHound.py?][bloodhound.py]]
- [[https://github.com/CravateRouge/bloodyAD][bloodyad]] and [[https://github.com/CravateRouge/autobloody][autobloody]]

- [[https://github.com/topotam/PetitPotam][petitpotam]]
- [[https://github.com/rofl0r/proxychains-ng][proxychains-ng]]

Local /nxc/ data will be saved under the current directory in /.docker-ad-nxc/.

Commands: =ad-run=, =ad-runit=, =ad-shell= for the container itself, plus the
wrappers =bloodhound-python=, =bloodhound-ce-python=, =certipy=, =coercer=, =nxc=,
=petitpotam=, =responder=, =smbclient= and =smbserver=.

/responder/ logs are saved under the current directory in /.docker-ad-responder/.

* bloodhound

Enable to runs multiple [[https://github.com/SpecterOps/BloodHound][BloudHound]] instances easily. Each instance will store
its Postgres and Neo4J data in the current directory. Defaults can be customized
via the [[./bloodhound/docker-compose.yml][docker-compose.yml]] and [[./bloodhound/.env][.env]] files.

#+begin_src shell
cd ~/projectA && bloodhound-run                          # ports 8111 / 7474 / 7687
cd ~/projectB && bloodhound-run projectb 8712 7475 7688  # name, then custom ports
#+end_src

Each instance is its own =docker compose= project, so several can run side by side.

* http-server

Basic HTTP(S) Python [[https://pypi.org/project/uploadserver/][uploadserver]]. It serves the volume mounted under //work/ on
the specified port (default /8000/) and provides file upload via
http://ip:8000/upload.

#+begin_src shell
http-server          # serves $(pwd) on :8000, uploads at /upload
http-server 9001     # another port
https-server         # same over TLS, with the certificate baked into the image
#+end_src

* pwn

Various pwn tools and python libs for CTF:

- [[https://github.com/Gallopsled/pwntools][pwntools]]
- [[https://github.com/pwndbg/pwndbg][gdb-pwndbg]]
- [[https://github.com/bata24/gef][gdb-gef]] (bata24's fork)
- [[https://github.com/mahaloz/decomp2dbg][decomp2dbg]]
- [[https://github.com/jerdna-regeiz/splitmind][splitmind]]
- [[https://github.com/yrp604/rappel][rappel]]
- [[https://github.com/david942j/one_gadget][one_gadget]]
- [[https://github.com/david942j/seccomp-tools][seccomp-tools]]
- [[https://github.com/0vercl0k/rp][rp-lin]] (rp++)
- [[https://github.com/niklasb/libc-database][libc-database]]
- [[https://github.com/marin-m/vmlinux-to-elf][vmlinux-to-elf]]
- [[https://angr.io/][angr.io]]
- [[https://github.com/Z3Prover/z3][z3]]
- [[https://www.sagemath.org/][sagemath]]

Commands: =pwn-run=, =pwn-runit=, =pwn-shell=. Inside the image, =gdb-pwndbg=
and =gdb-gef= start /gdb/ with the corresponding plugin; the bundled [[./pwn/files/gdbinit][gdbinit]]
also defines =openredir <file>= to redirect the inferior's stdin/stdout/stderr
to a file.

The image also ships a =pwn-init= command and two templates ([[./pwn/scripts/solve.py][solve.py]] and
[[./pwn/scripts/utils.py][utils.py]]) to bootstrap a challenge. =pwn-init= copies both into the current
directory (the mounted //work/), which is the first step for any challenge:

#+begin_src shell
pwn-shell                 # interactive shell, $(pwd) mounted at /work
pwn-init                  # drop solve.py + utils.py in the working directory
                          # pwn-init <dir>  targets another directory
                          # pwn-init -f     overwrites existing files
                          # pwn-init -s     also copy the solver skeletons
#+end_src

Edit /solve.py/ (set =BINARY=, =GDB=, =HOST=/=PORT= and =SSH_*= as appropriate.

#+begin_src shell
python3 solve.py          # run the binary locally
python3 solve.py GDB      # run locally under pwndbg
python3 solve.py REMOTE   # connect to HOST:PORT over TCP
python3 solve.py SSH      # run the challenge on the remote box over ssh
python3 solve.py SSH GDB  # debug it on the remote box via gdbserver
#+end_src

With =-s=, =pwn-init= also copies three solver skeletons: [[./pwn/scripts/angr_solve.py][angr_solve.py]],
[[./pwn/scripts/z3_solve.py][z3_solve.py]] and [[./pwn/scripts/sage_solve.py][sage_solve.py]].

#+begin_src shell
pwn-init -s               # copy angr_solve.py + z3_solve.py + sage_solve.py
python3 angr_solve.py
python3 z3_solve.py
python3 sage_solve.py
#+end_src

Make sure to check out what [[https://github.com/nobodyisnobody/tools][nobodyisnobody]] implemented and thank him for the
great work!

* recon

This image bundles some reconnaissance tools and scripts.

- [[https://github.com/projectdiscovery/alterx][alterx]]
- [[https://github.com/tomnomnom/assetfinder][assetfinder]]
- [[https://github.com/projectdiscovery/dnsx][dnsx]]
- [[https://github.com/lc/gau][gau]]
- [[https://github.com/projectdiscovery/httpx][httpx]]
- [[https://github.com/blechschmidt/massdns][massdns]]
- [[https://github.com/projectdiscovery/nuclei][nuclei]]
- [[https://github.com/d3mondev/puredns][puredns]]
- [[https://github.com/projectdiscovery/subfinder][subfinder]]
- [[https://github.com/projectdiscovery/tlsx][tlsx]]

It also provides the scripts /gimmesubs.sh/, /http-probe.sh/, /nuclei-auto.sh/
as well as /recon.sh/ which runs all previous 3.

This builds the image and loads the commands (=recon=, =gimmesubs=, =http-probe=,
=nuclei-auto=, =subs2web= are shell functions from [[./aliases.sh][aliases.sh]]):

#+begin_src shell
source aliases.sh
make recon

cd ~/engagements/acme

recon acme.com ~/lists/big.txt                 # subdomain enumeration for acme.me
                                               # then identify http servers and
                                               # scan them with nuclei
recon --http acme.com ~/lists/big.txt 80,443   # stop after http-probe on port 80 443
recon --subdomains acme.com ~/lists/big.txt    # only subdomains

# the stages are standalone commands too
gimmesubs -p acme.com
http-probe acme.com_*/subdomains.txt
nuclei-auto http-probe_*/live.txt
#+end_src

To run the image directly, without the wrapper functions (/massdns/ will need a
lot of ports):

#+begin_src shell
recon-run --help   # the image's own entrypoint, no argument rewriting
recon-shell        # interactive shell inside the image
#+end_src

* semgrep

Docker installation of [[https://github.com/semgrep/semgrep][semgrep's]] cli with support for the pro version. If you do
not wish to install the pro version, comment out the corresponding line in the
[[./semgrep/Dockerfile][Dockerfile]]. Otherwise the /semgrep/ cli will prompt for login during the
building of the image.

Commands: =semgrep= (the cli), =semgrep-pro-scan= (=semgrep scan --pro= with the
flags I use) and =semgrep-shell=.

* vsftpd

Exposes a FTP server via [[https://security.appspot.com/vsftpd.html][vsftpd]] on port 21 (and ports 30000-30009 for passive
mode). It serves the directory mounted as //home/ftpuser/, /FTP_USER/ and
/FTP_PASS/ can be passed as environment variables. The /vsftpd/ configuration
can be further edited in [[./vsftpd/entrypoint.sh][entrypoint.sh]].

#+begin_src shell
vsftpd "$(pwd)" skw foobar    # directory, user, password
#+end_src
